# CruzBuy cart-to-SSPR progress demo

The extension now has a **Cart helper** beside the existing Chat and Settings
navigation. It reads the Simple Shopping Cart layout supplied by the user at
`https://solutions.sciquest.com/apps/Router/SimpleCart`, without logging in on the
user's behalf or submitting anything to CruzBuy.

## Try it

1. Start the project with `./run.sh`. Reload the development extension after this
   update because it adds the `activeTab` and `scripting` permissions.
2. In the same browser/profile where that extension is loaded, log into CruzBuy
   yourself and open your cart. The separate WXT development browser does not
   inherit an existing Chrome profile's school login.
3. Click the extension icon while the cart is active. Sign into the extension with
   an approved account and choose **Cart helper**. Keep using the popup for cart
   capture: a separate extension tab is itself the active page and is not the cart.
4. Select **Use my cart**. Review every extracted item, quantity, supplier, amount,
   and total. Reading the cart does not submit it or send it to the backend yet.
5. Confirm estimated shipping/handling or leave them unknown. Never enter zero
   solely because the cart omitted a row. Select the actual funding type. Confirm
   the limited purchase scope and that the snapshot still matches the current cart.
6. Choose **Check paperwork** to send just the previewed purchase details to the
   authenticated backend. The result either asks for missing information or checks
   SSPR applicability with source links and supporting passages.

The supplied snapshot yielded one item, a 33.24 USD subtotal, 3.24 USD tax, and a
36.48 USD total. Shipping and handling were absent and therefore remain unknown.
The full supplied HTML was tested locally but was not copied into the repository.
The committed test fixture preserves the relevant structure with synthetic labels;
it excludes names, cart/contract identifiers, sessions, links, and page scripts.

## Scope and source handling

This is a deterministic source-backed **SSPR applicability demo**, not a complete
forms selector or a repaired general RAG. It does not call Qwen. Existing free-text
chat and the teammate's RAG remain unchanged by this feature. The dedicated
`POST /api/cart/guide` endpoint requires Firebase authentication and account
approval before reading policy sources or producing guidance.

Only the reviewed SSPR PDF (Rev. 12-2025, p.1) and interim BUS-43 PDF
(Jan. 26, 2026, p.9) are used. The server verifies their exact bytes against the
active public manifest entries; a missing or changed source stops the check. It
reads those pages directly rather than searching the full Chroma corpus. Threshold
constants are imported from the existing rule module and tested against the
existing source-provenance checks. No threshold is generated by a model.

Supported scope: one supplier, USD, one standalone goods purchase. Funding must be
confirmed; mixed funding, services, multi-year arrangements, and related-order
aggregation need further review. The helper uses the form's distinction between
non-federal amounts excluding tax and federal amounts including tax, with estimated
shipping/handling included in the reviewed estimate. CruzBuy's totals are estimates,
not finalized supplier charges. A contract link alone is not assumed to establish
an exemption, a valid sourcing choice, or permission to purchase.

At or above the applicable form threshold, the helper links SSPR and explains that
Section I and the sourcing choice determine further sections. Below it, it says
the form's amount threshold is not met; it does not say no other paperwork is needed.
BUS-43 is cited as purchasing-policy context, not a complete exception/contract
determination. Campus-specific requirements remain for Procurement to confirm.

## Validation and presentation

Run the synthetic regression scenarios:

```sh
./venv/bin/python -m scripts.evaluate_cart_demo
```

The CSV under `data/evaluation` records the expected and actual result for eight
synthetic cases, including threshold boundaries, federal tax treatment, and unknown
funding/shipping. Report those as deterministic workflow checks, not Qwen accuracy
or successful real-user purchasing trials. No cart is modified for a high-value test.

For screenshots: show the CruzBuy cart, the extraction preview, the funding question,
and the cited result. Mask account/cart identifiers before sharing. The native
Chrome session was not available to inspect; extraction was validated against the
supplied HTML and synthetic fixtures, while a live extension click in the signed-in
cart still needs the user's verification. Unsupported layouts fail visibly.

The reader uses temporary active-tab access on a user click and validates the exact
host/path. There is no background cart scraping, persistent cart storage, collection
of the cart owner/contract IDs, automatic supplier navigation, form filling, or order
submission. Values in cart text are treated as data and never model instructions.
