# Chunk enrichment v1: result — 2026-10-29

Experiment: contextual enrichment of the chunk corpus (per-chunk header naming the
policy/section/thresholds + 3–5 likely employee questions, generated by qwen3:32b,
2,955 unique chunks, `evaluation/benchmarks/generate_enrichment.py`). Ingested into a
separate collection (`uc_policies_enriched`); the default `uc_policies` collection was
never touched. Same benchmark, answerer (qwen3:8b) and judge (qwen3:32b, temp 0) as
the A/B run.

| run | CORRECT | PARTIAL | WRONG | C+P |
|---|---|---|---|---|
| baseline (no enrichment) | **39** | 17 | **4** | **56** |
| enrichment in retrieval + LLM context | 36 | 18 | 6 | 54 |
| enrichment in retrieval only (raw chunk to LLM) | **39** | 14 | 7 | 53 |

Result files: `ab_rules_enriched_qwen8b.json`, `ab_rules_enriched_embedonly_qwen8b.json`
(+ `.judge.json`).

## Verdict: not adopted

Neither variant beats the baseline. Serving the generated text to the LLM dilutes the
answer context (36/60); keeping it retrieval-only recovers the correct count but
worsens the wrong count (7 vs 4) — the generated questions pull in near-topic chunks
that read relevant to BM25/the reranker but answer a *different* rule, and those
displace the chunk that carried the exact threshold. The default pipeline and
collection stay exactly as benchmarked in the A/B (39/17/4).

Plumbing kept (harmless when no enrichment file is set, useful for v2):
- `ENRICHED_CORPUS_PATH` ingest hook, sha1-keyed per raw chunk text
- `raw_text` metadata: enriched text is searchable, the LLM gets the original chunk

## What the run still bought us

The 2,955 enriched chunks contain ~11k generated (question, chunk) pairs — exactly
the synthetic training set needed for the embedder fine-tune (plan item 2), which
targets the same failure mode directly (teach the embedder which chunk answers which
phrasing) without putting generated text in the index at all. That is the next
experiment; enrichment v2 (if any) should generate disambiguating headers only, no
questions, and be measured with retrieval recall@k before any end-to-end run.
